如何优雅地直连无公网 IP 的远程 GPU 服务器

发表于 2026-09-13 |

前言

故事是这样的。

我在做 AIGC 相关的开发，主力环境是一台没有公网 IP 的 GPU 实例以及一台阿里云灵构服务器，主要用来跑 ComfyUI、训练模型。

但使用过程中有几个让人难受的问题：

  • 阿里云官方自带的远程桌面控制延迟巨大，体验感太差
  • 文件传输太过麻烦，阿里云灵构需要借助网盘中转，而魔搭 WebIDE 有文件大小限制

我第一时间想到的解决办法就是内网穿透，不过第三方的穿透工具不太稳定，要么限速要么频繁掉线。刚好手上有一台 99 元的阿里云服务器，我寻思着不用也是浪费，干脆直接拿它来当做跳板机

不过我并没有考虑自建 frp 的方式来实现穿透，因为安装软件比较麻烦，每台目标机器都要安装 frpc 客户端的话太消耗时间，

本来薅来的免费 GPU 算力时长就有限，所以省事高效是第一原则。

于是我选择了 SSH 反向隧道的方式来穿透

我想要的效果是：

  • 本地 VS Code 直接打开远程 GPU 的终端，并实现文件实时编辑和传输
  • 本地浏览器直接访问 127.0.0.1:8188 操作 ComfyUI
  • 服务器和本地电脑重启后自动打通隧道

实现原理

穿透的本质就是借道，借有公网IP服务器的道

网络拓扑如下：

关键点只有三个：

  1. GPU 主动连阿里云（因为 GPU 能出网，阿里云有公网）
  2. 建立反向隧道（-R）：把 GPU 的端口“伸”到阿里云本机
  3. 本地再连阿里云（-L）：把本地端口“引”到阿里云

最终效果：

  • localhost:8188 → 阿里云 → GPU 的 ComfyUI
  • VS Code ssh GPU → 阿里云 → GPU 的终端

准备工作：阿里云侧

确保阿里云允许端口转发：

这里需要明白的是，由于我们走的是 SSH 22 端口通道，所以无需去阿里云安全组开放 2222 和 8188 等端口，有公网 ip 即可，22 端口默认都是开放的.

同时开启ssh保活检测 (非必须操作, 建议加上):

  • ClientAliveInterval 30 : 每 30 秒服务端问一次客户端”你还活着吗”
  • ClientAliveCountMax 3 : 连续 3 次没回应就断开连接

阿里云加这两个的主要目的是:

  1. 激发 autossh 重连: 连接被断开但进程还在的情况下, GPU服务端的autossh 会误以为还处于正常通信状态, 阿里云配置作为一个保活补充
  2. 避免长时间假死时端口一直占着, 导致新连接建立不了

VS Code 可以同时连多台 GPU，互不干扰。

最优雅的方法就是只维护SSH端口, 打通终端直连后, 本地电脑可以随意转发GPU任意端口, 无需占用阿里云端口资源.

否则, 则需要在GPU上挨个执行ssh -R进行反向映射, 维护起来稍微麻烦一些

两种方案对比:

方案A：只打通 22（直连 gpu-N） 方案B：挨个 -R
要敲的命令 就一条 ssh gpu-1（或 VS Code 连一下） GPU 上写 N 条：ssh -R 3000:... -R 8080:... -R 8188:... root@阿里云
以后新增端口（比如突然起个 6006） 本地加一行 -L 6006:127.0.0.1:6006 就行，GPU 不用碰、不用重连 得登回 GPU 改命令、杀旧进程、重起 -R，阿里云还得再腾一个端口
占用中间资源 0 个阿里云端口 N 个阿里云本机端口（3000/8080/8188全占一遍，撞了就静默失败）
断线恢复 保活那条 SSH 就行，全跟着活 每个 -R 各自可能悄断，得挨个查
谁动手 只动你 Mac 每次加端口都要登 GPU + 动阿里云
像什么 拉一根万能水管到 GPU，想接啥龙头本地拧一下 每个水龙头都单独从 GPU 拉一根管子到阿里云，满地管子

问题汇总

  1. ssh gpu登录GPU提示需要输入root@127.0.0.1 password

    问题出在公钥上, 检查本地comfy_key.pub公钥和GPU中authorized_keys中存储的公钥是否一致

    另外有一点需要注意的是, 不要使用老版ssh-rsa格式密钥, 目前很多新系统默认将其禁用了, 推荐使用新的ssh-ed25519格式密钥

  2. 关于密钥问题

    本地连接阿里云和连接GPU服务器可以使用不同的密钥, 比如:

    隧道建立是先连接阿里云服务器, 成功后再连接GPU服务器, 阿里云只负责数据中转, 而不会拿着comfy_key密钥去替我们连接GPU, 这点需要明白,

    所以, 他们不一定非得使用相同密钥对, 之前我们为了方便管理和使用, 共用了相同的comfy_key密钥

  3. root用户和admin用户

    阿里云灵构的GPU服务器, 默认用户为admin, 在服务器上执行echo ~可以查看

    如果我们将comfy_key公钥放在admin下的.ssh/authorized_keys文件中, 那么本地电脑config配置需要以admin身份登录:

    同理, 如果放在root下的.ssh/authorized_keys文件中, 则需要将User字段改为root, 你以什么身份去登录, 它就会去那个目录下找.ssh/authorized_keys, 这是一个小细节, 需要注意

  4. 浏览器输入127.0.0.1:8189一直空转无法访问ComfyUI

    这里涉及到一个端口转发先后顺序的问题, 场景比如：

    • 本地 Mac 转发：Mac本地8189 → 阿里云127.0.0.1:8189
    • GPU 反向隧道：GPU本机8189 → 阿里云127.0.0.1:8189

    时序如下:

    启动顺序 阿里云侧8189状态 结果
    Mac自启先跑（ProxyJump建连） 阿里云侧只是“连一下8189”，没监听者 → 连接被拒，但ssh不报错 Mac隧道建了，但中间是空的
    GPU反向隧道后起 -R 8189 想在阿里云监听8189，发现没冲突反而能绑上 ✅ 但 Mac 那条旧连接已经失败了，不会自动重连
    Mac自启先跑 + GPU反向隧道后起 Mac那条通道里流量一直不通，你浏览器访问就是转圈/空响应 ❌ 表现就是“连不上但又不报错”

    更糟的情况：如果你之前手动起过某个 autossh -R 占着阿里云8189，GPU 上再起 -R 直接报 bind failed，反向隧道静默退出，你完全看不到错。

    所以, 不出错的办法就是: 先启动GPU反向隧道, 再起本地转发
